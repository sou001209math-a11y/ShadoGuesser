Shado Guesser 基本設計書

05-02：入力UI

本設計書では、 Shado Guesserにおいてプレイヤーが 回答するカードを指定するための入力UI、 カードサジェスト、 カード選択、 回答ボタン、 回答要求、 および回答確定までの基本操作を定義する。

カード検索には、 ゲーム開始時に固定されたData Versionに対応する Version別静的Search Indexを使用し、 文字入力ごとの検索はブラウザ内で実行する。

1. 目的

入力UIは、 プレイヤーがカード名を入力し、 サジェスト候補から正式なカードを選択した後、 明示的に回答を確定するためのUIである。

長いカード名を完全入力する必要がないよう、 カード名の一部分から候補を検索できる構造とする。

基本方針
  • カード名を入力する。
  • 検索はブラウザ内で行う。
  • 現在のゲームで回答可能なカードだけ検索対象とする。
  • 候補から正式なカードを選択する。
  • 選択時にcard_idを保持する。
  • 候補を選んだだけでは回答しない。
  • 回答は「回答する」ボタンのみで確定する。
  • Enterキーでは回答しない。
  • 正式な回答可否・判定はサーバー側を正とする。

サジェスト欄は常時表示せず、 検索条件を満たし候補が存在する場合に表示する。

3. カード名入力欄

回答候補を検索するための テキスト入力欄を1つ設置する。 

[ カード名を入力                       ]
  • 入力形式はテキスト。
  • カード名の一部分のみの入力を許可。
  • 完全一致入力を要求しない。
  • 入力文字列からサジェストを生成。
  • カード名以外を検索する専用入力欄は設置しない。

5. Versionの扱い

ゲーム内部では data_version_id を固定する。

BrowserがSearch Indexを取得する際は、 そのVersionに対応する version_code を使用する。 

data_version_id

→ Server / D1 / Durable Objects内部


version_code

→ Browserへ公開可能なVersion表記
→ Search Index filename

ゲーム

data_version_id = 内部Version A

version_code = 2026-07-28-01

↓

Browser

card-search-index-2026-07-28-01.json

dataVersion という曖昧な名称は原則使用しない。

6. ゲーム途中のVersion変更禁止

ゲーム開始後にCurrent Versionが変更されても、 進行中ゲームのSearch Indexを 新Versionへ変更しない。 

ゲーム開始

data_version_id = A
version_code = A

↓

Current = Bへ変更

↓

進行中ゲーム

Version Aを継続使用


新規ゲーム

Version Bを使用

DailyについてCurrent変更が発生した場合は、 07で定義したDaily停止仕様が別途適用される。

  • skill_text。
  • flavour_text。
  • atk。
  • life。
  • cost。
  • tribes。

9. 正解情報との分離

  • 正解card_idをSearch Indexへ記録しない。
  • 正解card_idをHTMLへ埋め込まない。
  • ゲーム開始時に正解カードをBrowserへ送らない。
  • Browserだけで正解判定できる構造にしない。

21. 選択後の文字編集

カード選択後に入力文字列が変更された場合は、 選択状態を解除する。

22. 回答ボタン

回答確定用の専用ボタンを設置する。 

[ 慈愛の凛華・オルテニア             ]

                [ 回答する ]
  • 回答は「回答する」ボタン押下時のみ。
  • 候補選択だけでは回答しない。
  • 文字入力だけでは回答しない。
  • 選択済みcard_idを使用する。
  • 回答処理開始直後に操作不可にする。

23. Enterキー

Enterキーによる回答送信は禁止する。
  • Enter → 回答しない。
  • 候補選択後Enter → 回答しない。
  • 完全一致入力後Enter → 回答しない。
  • 回答は「回答する」ボタンのみ。

HTML <form> を利用する場合も、 標準Submitによって回答処理が実行されないよう制御する。

24. IME入力

日本語入力ではIME変換途中のKeyboard Eventが発生するため、 composition状態を考慮する。

  • IME変換途中を正式な回答操作として扱わない。
  • composition中のEnterを回答に使用しない。
  • 通常時のEnterも回答には使用しない。

27. 正式な回答Request

回答時にはカード名文字列ではなく card_idを送信する。 

{
    "requestId": "...",
    "card_id": "10201110"
}

実際のEndpoint・Session識別情報等は 06で定義する。

28. requestId

正式な回答Requestごとに 一意の requestId を付与する。

  • 新しい回答操作には新しいrequestId。
  • 同一回答の通信再試行では同じrequestIdを使用。
  • Serverが同じrequestIdを再受信しても回答を二重処理しない。
回答操作A

requestId = A


↓

通信障害


↓

回答操作Aを再確認

requestId = A


↓

二重Guessにしない

31. Battleの追加検証

Battleではさらに以下を確認する。

  • 送信者が参加Playerである。
  • 現在そのPlayerの手番である。
  • ゲームがplaying状態。
  • Server時刻がdeadlineより前。

32. Battle deadline

Serverが回答Requestを処理する時点で

であれば、 PlayerのGuessを先に成立させない。

34. 回答成功後

GuessがServerで正式に成立し、 ゲームが継続する場合は 次の入力へ戻る。

  • Serverの正式結果を反映。
  • 回答履歴更新。
  • 回答回数更新。
  • 入力文字列を空にする。
  • selectedCardIdをnullにする。
  • サジェストを閉じる。
  • isSubmitting解除。

35. 通常ゲーム終了

正解・回答上限・降参・Battle勝敗等により 通常のゲーム終了が確定した場合は、 次の入力状態へ戻さない。

38. Daily停止時の入力内容

Daily停止が確定した場合、 その時点で入力していたカードを 回答として扱わない。

停止後にその入力を再送できるUIも表示しない。

39. 通信失敗

回答Requestを送った後に通信が切れ、 結果を受信できなかった場合、 Clientだけで成功・失敗を判断しない。

  • 回答回数をClientだけで減らさない。
  • 回答履歴をClientだけで追加しない。
  • 同じrequestIdで処理結果を確認可能にする。
  • Server状態確定まで別Guessを送信しない。

42. 同一カードの再回答

  • 同じカードを再び検索可能。
  • サジェストから除外しない。
  • 「回答済み」警告を表示しない。
  • 正式に送信すれば通常の1Guess。
  • 回答回数も通常通り1回消費。

47. Daily

Dailyの入力UIは 基本的にSoloと共通とする。

  • Search方式共通。
  • Suggestion共通。
  • 回答Button共通。
  • 最大10回答。

  • daily_controlsがsuspendedなら入力不可。

48. 2人出題

正解カード設定後、 回答者は共通入力UIを使用する。

  • カード検索UI共通。
  • 回答Button共通。
  • 回答上限10回。
  • ヒントなし。
  • 回答者は別UIの降参操作を利用可能。
  • 出題者の切断後もServer Stateが継続可能なら入力を続行。

49. 2人出題の出題者側カード選択

出題者が正解カードを選択する画面は、 回答者のGuess入力とは目的が異なるため 別状態として扱う。

正解設定後のanswer_card_idを 回答者Clientへ送信しない。

57. 入力UIで設置しない機能

  • 読み仮名専用検索。
  • 音声回答専用機能。
  • 履歴からの自動重複排除。
  • 同一カード回答警告。
  • Enterキー回答。
  • 文字列のみを正式回答として送信する機能。
  • カード名以外の項目検索。
  • 文字入力ごとのWorker検索。
  • 文字入力ごとのD1検索。
  • ゲーム対象外カードの回答。
  • ゲーム途中のSearch Index Version切替。
  • Clientだけでの正式回答判定。

60. Clientの範囲判定はSecurity境界ではない

Search IndexやJavaScriptが 対象外カードを隠していても、 それをSecurity対策として扱わない。

DevTools等でClientを改変される前提で、 Serverが正式に検証する。

61. UI上のエラー

入力方法に起因する軽微な状態は 画面内で処理する。

状態 処理
候補未選択 回答Button disabled
文字編集で選択解除 再選択を要求
Search Index未読込 回答不可
Search Index取得失敗 再試行導線
通信中 回答Button disabled

62. Server Error

Serverがデータ異常等を返した場合は、 入力欄へ適当な値を補完して続行せず、 03・06で定義するerror状態へ移行する。
