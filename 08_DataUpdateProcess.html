Shado Guesser 基本設計書

08：データ取得・更新手順

本設計書では、 Shado Guesserで使用するカードデータについて、 公式サイト由来の構造化Source Dataの取得、 Source Archive、 Importer、 Mapping、 Normalized Data、 Draft Version、 Validation、 Diff Report、 Search Index、 Published、 Current変更までの 正式なデータ更新手順を定義する。

2. Draft前とDraft後のValidation

「Validation」という言葉を 1種類の処理として扱わない。

段階 役割
Source Schema Validation Source構造そのものがImporterで処理可能か確認
Mapping Validation Source IDを既知Mappingで変換可能か確認
Data Validation 生成されたDraft Snapshotがゲーム利用可能か確認
Search Index Validation Version別Search IndexがDraftと一致するか確認

Source SchemaやMappingが成立せず Normalized Candidate自体を正常生成できない場合は、 通常のDraft Versionを作成しない。

一方、 Normalized Candidateを正常生成できた後は Draft Versionを作成し、 そのDraftに対して正式なData Validationを行う。

3. 正式Source Data

公式サイトがカード情報表示等に使用している 構造化JSON等の機械可読データを 正式Sourceとして使用する。

HTML画面からカード内容を読み取って 全カードデータを再構成する方式より、 公式側の構造化Dataを優先する。

65. Data Validation

Draft Version生成後、 そのDraft Snapshotが ゲーム利用可能かData Validationを実施する。

Data Validation Errorが1件でも存在する場合、 Publish不可。

66. Validation Level

Level 処理
Error Publish不可
Warning 管理画面表示。Error 0ならReview後Publish可能

67. Errorの原則

Card判定・回答範囲・画像表示等に影響し、 正常なGame動作を保証できない問題は Errorとする。

68. Warningの原則

Card Name変更
1件

skill_text変更
8件

Gameを壊さないが 管理者確認が必要な変化をWarningとする。

120. Old Published Version

初期版では Old Published Versionを自動削除しない。

進行中GameがOld Versionを参照する可能性があるためである。

121. Old Search Index

Old Version用Search Indexも 初期版では自動削除しない。

Old data_version_idで進行するGameが 対応version_codeのIndexを取得できるようにする。

122. Source Archive公開禁止

Source ArchiveをPublic Static Fileとして配信しない。

一般Userへ必要なのは Shado Guesser用に生成したSearch Index等の公開Dataのみ。

123. Source URL

可能な場合、 取得元Official URL・取得経路を Source Manifestへ記録する。

URLへ一時TokenやSession情報が含まれる場合は 秘密部分を保存しない。

124. Source取得時の安全性

必要な公開Card Dataのみを対象とし、 個人の認証情報を Card Update Pipelineへ持ち込まない。
