Shado Guesser 基本設計書

05-07：結果画面

本設計書では、 Shado Guesserにおいて通常のゲーム終了が確定した後に表示する 結果画面について、 ゲームモードごとの表示内容、 正解カード、 回答数、 使用ヒント、 経過時間、 対戦結果、 およびDailyのX共有機能を定義する。

Daily停止、 データ異常等の 通常のゲーム終了ではない状態 についても、 結果画面との違いを本書で明確にする。

1. 目的

結果画面は、 正常にゲーム終了条件が成立した後に プレイヤー自身のプレイ結果を確認するための画面である。

単に「正解」「不正解」だけを表示するのではなく、 回答回数、 使用したヒント、 経過時間、 Battle時の勝敗等、 ゲームモードに応じた結果情報をまとめて表示する。

結果画面の基本方針
  • 通常のゲーム終了後に表示する。
  • 通常終了時は正解カードを公開する。
  • ゲーム中の回答履歴を維持する。
  • 終了後も回答履歴を閲覧可能とする。
  • 終了後は新しい回答を行えない。
  • モードごとに必要な結果情報のみ表示する。
  • ヒント結果を表示するのはSolo / Dailyのみ。
  • 2人出題 / Battleではヒント結果を表示しない。
  • Dailyでは安全なX共有導線を設置する。
  • Daily共有では正解を特定できる情報を含めない。

2. 通常終了と非通常終了

Shado Guesserでは、 すべてのゲーム停止状態を 「結果画面」へ送るわけではない。

状態 結果画面 正解公開
正解 表示 する
回答上限到達 表示 する
通常の降参 表示 する
Battle勝利 / 敗北 / 引き分け 表示 する
Daily suspended 表示しない しない
データ異常によるerror 表示しない しない

DAILY_SUSPENDED は、 正解・失敗・降参等の通常終了理由として扱わない。

  • 降参として記録しない。
  • 回答上限到達として扱わない。
  • 正解カードを返さない。
  • X結果共有の対象にしない。

4. Daily停止画面

Daily停止時は以下の専用メッセージを表示する。 

本日はカード更新もしくは不具合の影響で
デイリーは停止されています。
またAM5:00以降に遊びに来てください。
  • Result Titleを表示しない。
  • 回答数を最終結果として表示しない。
  • 正解カードを表示しない。
  • 正解card_idをClientへ公開しない。
  • ヒント結果を表示しない。
  • 通常の再挑戦Buttonを表示しない。
  • X共有Buttonを表示しない。

8. 結果画面と回答履歴

  • 終了後も回答履歴を維持する。
  • 最新回答が上の順序を維持する。
  • 履歴カードのAccordion操作を維持する。
  • 各回答の判定内容を振り返れる。
  • 終了後の履歴から新しい回答を発生させない。

9. 正解カードの公開

通常のゲーム終了が確定した場合のみ、 それまで秘匿していた正解カードを公開する。 

正解カード

┌────────────────────┐
│                    │
│     CARD IMAGE     │
│                    │
└────────────────────┘

カード名
  • 正解カード画像を表示する。
  • 正解カード名を表示する。
  • カード名は全文表示を基本とする。
  • 正解時も公開する。
  • 回答回数切れでも公開する。
  • 通常の降参時も公開する。
  • 2人出題終了後も公開する。
  • Battle終了後も公開する。

10. 正解を公開しない状態

  • Daily suspended。
  • データ異常によるerror。
  • その他、正常なGame Endとして確定していない状態。

「ゲーム処理が止まった」 というだけで正解を返してはならない。

11. 正解カードのData Version

結果画面で表示する正解カードは、 ゲーム開始時に固定された data_version_id に属するカード情報を使用する。

結果画面だけCurrent Versionのカード情報へ 差し替えない。

12. data_version_id / version_code

data_version_id

→ Server / D1内部
→ Gameが固定するVersion識別子


version_code

→ 人間向けVersion表記
→ 例：2026-07-28-01

dataVersion という曖昧な名称は原則使用しない。

13. 正解カード画像

カード画像は04で定義した image_ref を使用する。

14. 正解カード詳細

結果画面の最低必須表示は カード画像 + カード名 とする。

将来正解カード詳細を追加する場合も、 05-04で定義したNormalized Dataを再利用し、 Result専用の別カードデータ構造を作らない。

32. Timeout Random Guess

  • 通常回答と同じ共有履歴へ追加。
  • 通常の判定表示を使用。

  • Result Screenで特殊な別カテゴリにはしない。

43. Daily共有の目的

同じDaily期間中は 同じ正解へ挑戦するため、 他Playerへ正解が分かる共有内容は禁止する。

正解カード名・カード画像・判定内容・具体的Hint内容等を 共有文へ含めない。

52. Dailyの再挑戦

正常終了したDailyは、 同じDaily期間中でも再挑戦を許可する。

  • 1日1回制限なし。
  • Account / Device制限なし。
  • 新しいGameSessionDOを作成可能。
  • 同一daily_keyでは同じ正解カードを使用。

53. Daily停止中の再挑戦

58. 降参時の履歴

  • 降参以前の回答履歴を維持。
  • 「降参」という履歴Cardは作らない。
  • Result Titleで降参を示す。
  • 通常降参終了後は正解カード公開。

59. 終了後の入力UI

  • 新しい回答不可。
  • 回答Button不可。
  • Suggestionから回答不可。
  • 新しいHint不可。
  • 履歴閲覧可。
  • 共有等の終了後操作可。

60. Result Screenの表示位置

ゲーム終了直後に Playerが認識できる位置へ表示する。

必要に応じてResult領域が見える位置へ 画面を移動する。

ページ最下部へ追加するだけで PlayerがResult表示に気づかない構造にしない。

61. 小型Modalだけで完結させない

71. Host Siteとの競合対策

  • Result Screenは #sg-app 内。
  • Result系Classは sg-result-。
  • Daily停止は sg-daily-stop-。
  • 汎用的すぎる .result 等だけを使用しない。
  • Host SiteのButton Styleへ依存しない。
  • WordPress固有CSS / JSへ依存しない。

72. Result Screenで設置しないもの

  • 同じ終了済みGameへ戻って回答を再開する機能。
  • 回答数手動修正。
  • 時間手動修正。
  • 回答履歴削除。
  • Daily正解Card名を含むSNS共有。
  • Dailyの具体的Hintカテゴリ共有。
  • Battle履歴のPlayer別色分け。
  • 2人出題Hint結果。
  • Battle Hint結果。
  • Client単独の正式勝敗決定。
  • Daily停止時の正解Card表示。
  • Daily停止時のX結果共有。

73. 終了後の再プレイ導線

通常終了後は、 必要に応じて以下の導線を設置できる。 

[ もう一度遊ぶ ]

[ もう一度挑戦 ]

[ モード選択へ戻る ]

これは 進行中GameのResetとは別 である。

74. Daily再挑戦Button

正常終了したDailyでは 同一daily_keyへ再挑戦する導線を設置可能。

現在のdaily_keyが suspendedになっている場合は 再挑戦を開始させない。

  • 再プレイButtonの文言・配置。

  • Battle切断勝敗の最終表示文言。
  • Daily Stop Screenの具体的な装飾。

これらはGame Resultの意味そのものを変更せず、 UI実装時に調整する。

78. 本設計書の位置付け

本書「05-07 結果画面」は、 正常に終了したShado GuesserのGame Resultを どのようにPlayerへ表示するかを定義する。

Daily SuspendやData Error等は 通常Resultと明確に分離し、 正解情報を誤って公開しないことを重要原則とする。
