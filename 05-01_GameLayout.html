Shado Guesser 基本設計書

05-01：ゲーム画面レイアウト

本設計書では、 Shado Guesserにおけるゲーム画面全体の構成、 各UIエリアの配置方針、 ゲームモードごとの差分、 および将来WordPressサイトへ組み込む場合にも対応できる 基本レイアウト方針を定義する。

1. 目的

Shado Guesserのゲーム画面は、 カード名を推測して回答し、 回答結果を確認しながら 正解カードを絞り込んでいくことを主目的とする。

PC・スマートフォンの双方から利用されることを前提とし、 画面幅が異なる環境でも ゲームの基本的な操作性を維持する。

基本方針
  • Shado Guesser本体は独立したWebアプリとして動作可能とする。
  • ゲームUIは外側のサイト構造へ依存しない。
  • 将来WordPressへ組み込む場合もゲーム本体の大幅変更を不要とする。
  • PC・スマートフォン双方で利用可能とする。
  • ゲーム操作に不要なUIは極力設置しない。
  • Solo / Daily / 2人出題 / Battleで可能な限り共通UIを使用する。
  • モード固有機能のみ表示・非表示を切り替える。

2. ゲームアプリのルート要素

Shado GuesserのゲームUI全体は、 専用ルート要素 #sg-app の内部へ構築する。 

<div id="sg-app">

    Shado Guesser

</div>
  • ゲームUIを #sg-app 内へ集約する。
  • ゲーム用CSSクラスには sg- プレフィックスを使用する。
  • 外側サイトのheader / footerをゲーム状態管理へ利用しない。

3. 独立Webアプリとしての配置

6. レイアウトの共通化

各モードごとに完全に異なるゲーム画面を作らず、 共通コンポーネントを可能な限り再利用する。

モード 基本画面 主な差分
Solo 共通 ヒント・降参を利用可能
Daily 共通 ヒント・降参・Daily固有状態を利用
2人出題 共通 回答者は降参可能。ヒントなし
Battle 共通 手番・120秒Timer・退出等を追加。ヒント・降参なし

履歴カード・カード詳細・回答入力等の 共通部分を再利用し、 モード固有部分だけを切り替える。

9. 回答入力エリア

ゲーム情報エリアの下部に カード名を入力する回答入力エリアを配置する。

ゲーム中に最も頻繁に操作するため、 PC・スマートフォン双方で 十分な操作領域を確保する。 

┌────────────────────────────────────────────┐
│                                            │
│   [ カード名を入力                      ]  │
│                                            │
│               [ 回答する ]                 │
│                                            │
└────────────────────────────────────────────┘
  • カード名入力欄を配置する。
  • 入力中はサジェスト候補を表示する。
  • サジェストからカードを正式選択する。
  • 選択したcard_idを内部保持する。
  • 「回答する」ボタンで正式回答する。
  • Enterキーでは回答を確定しない。
  • 回答処理中は回答ボタンを一時無効化する。

詳細は05-02および05-09で定義する。

10. 回答不可状態

ゲーム状態上、 回答できない場合は回答入力UIを無効化する。

主な回答不可状態：

  • ゲーム開始前。
  • 回答送信処理中。
  • ゲーム終了後。
  • Battleで相手の手番。
  • Battleの正式なdeadline到達後。
  • 再接続・状態同期中。
  • Daily停止状態。
  • データ異常によるerror状態。

16. ヒントの基本表示

ヒントはSolo / Dailyのみで使用する。

  • ヒントカテゴリは任意順で選択可能。
  • 複数カテゴリ使用可能。
  • 同一カテゴリは1ゲームにつき1回のみ。
  • 使用済み情報はゲーム中表示し続ける。
  • ヒント使用で回答回数を消費しない。

「使用回数に上限なし」という表現は使用しない。

正確には、 複数カテゴリを使用できるが、各カテゴリは1回のみ とする。

  • Guess判定へ使用しない。
  • 長文に応じてカード高さを自然に伸ばす。

39. ページ再読み込み

ページ更新・F5等が発生しても、 有効なゲームSessionが存在する場合は 可能な限り同じゲーム状態へ復帰する。

モード Reload後
Solo Resume可能
Daily Resume可能。ただしDaily停止時は再開不可
2人出題 Session条件に従ってResume
Battle reconnectToken等を使用して再接続

ページ更新を ゲームリセット操作として扱わない。

40. 再接続中UI

サーバー状態を再取得している間は、 誤った古い状態で操作できないようにする。 

ゲーム状態を復元しています...
  • 回答入力を一時無効化。
  • 危険な操作を一時無効化。
  • 完全Snapshot取得後に画面を復元。

41. Daily停止画面

当日のDailyが停止された場合は、 通常のゲーム結果画面ではなく Daily停止専用状態を表示する。 

本日はカード更新もしくは不具合の影響で
デイリーは停止されています。
またAM5:00以降に遊びに来てください。
  • 回答入力を表示しない、または無効化する。
  • ヒント操作不可。
  • 降参操作不可。
  • 正解カード非公開。
  • 通常の成功・失敗結果として表示しない。

42. ゲーム終了時

通常のゲーム終了時は、 ゲーム中UIから05-07で定義する 結果表示へ移行する。

  • 新しい回答不可。
  • 新しいヒント使用不可。
  • 通常終了時は正解カード表示。
  • 回答履歴は確認可能。

Daily停止やデータerrorは 通常結果とは別状態とする。

45. CSS競合対策

Shado Guesserを独立運用した場合にも、 将来外部サイトへ組み込んだ場合にも CSS競合しにくい構造にする。

  • ルートは #sg-app。
  • 専用Classは sg- prefix。
  • .button や .card のような汎用Classだけを使用しない。
  • 外部サイトのh1・button等へのCSS指定へ依存しない。
  • 可能な限り #sg-app 内部へStyle影響を限定する。

46. JavaScript実装方針

  • ゲームモードごとに画面HTML全体を複製しない。
  • 履歴カード生成処理を共通化。
  • カード詳細表示を共通化。
  • 回答入力エリアを共通化。
  • モード固有操作だけ条件表示。
  • サーバーからの状態Snapshotを元に描画する。
  • 古いstateVersionによる画面巻き戻りを防ぐ。
