Shado Guesser 基本設計書

05-03：履歴表示

本設計書では、Shado Guesserにおいてプレイヤーが回答したカードを ゲーム画面上へ蓄積して表示する「回答履歴」の構造、 表示順、アコーディオン動作、および各ゲームモードでの共通表示仕様を定義する。

1. 目的

回答履歴は、これまでに回答したカードとその判定結果を プレイヤーがいつでも確認できるようにするためのUIである。

Shado Guesserでは、過去の回答結果を比較しながら 正解カードを絞り込むことがゲームの中心となる。

そのため、回答履歴は単なる記録ではなく、 ゲーム中に繰り返し参照する主要な情報領域として扱う。

履歴表示の基本方針
  • 回答したカードをすべて履歴へ残す。
  • 最新の回答を最上部へ表示する。
  • 履歴1件を1つのカードとして表示する。
  • 各履歴カードは個別に開閉できるアコーディオン形式とする。
  • 閉じた状態でもカード画像とカード名を常時表示する。
  • PC・スマートフォンで基本構造を共通とする。

2. 回答履歴の配置

回答履歴は、ゲーム画面の回答入力エリアおよび操作エリアより下に配置する。 

┌────────────────────────────────────────────┐
│               ゲーム情報                   │
├────────────────────────────────────────────┤
│               回答入力UI                   │
├────────────────────────────────────────────┤
│          ヒント / 降参 等                  │
├────────────────────────────────────────────┤
│                                            │
│               回答履歴                     │
│                                            │
│        最新の回答                          │
│                                            │
│        1つ前の回答                         │
│                                            │
│        さらに過去の回答                    │
│                                            │
└────────────────────────────────────────────┘

回答が増えるたびに、 回答履歴エリアの最上部へ新しい履歴カードを追加する。

3. 履歴の表示順

回答履歴は、 新しい回答ほど上、古い回答ほど下 となるように表示する。

1回目、2回目、3回目の順に回答した場合、 画面上では以下の順番となる。 

回答履歴

3回目の回答
2回目の回答
1回目の回答
表示順：新しい順（降順）

回答追加時に既存履歴の末尾へ追加するのではなく、 表示上は最新回答が先頭になるようにする。

4. 履歴件数

ゲーム中に行われた回答は、 原則としてすべて履歴へ表示する。

状態 履歴表示
回答0回 履歴カードなし
回答1回 1件表示
回答5回 5件表示
回答10回 10件表示
  • 古い履歴を途中で削除しない。
  • 一定件数を超えた履歴を非表示にしない。
  • ページ分割は行わない。
  • ゲーム中の全回答を同一画面上で確認可能とする。

5. 履歴カードの基本構造

回答1件につき、1つの横長カードを作成する。

履歴カードは、 「ヘッダー部分」と「詳細部分」の2つで構成する。 

┌────────────────────────────────────────────┐
│                                            │
│ ▶ [カード画像]  カード名                   │
│                                            │
├────────────────────────────────────────────┤
│                                            │
│      カード詳細情報                        │
│      ※展開時のみ表示                       │
│                                            │
└────────────────────────────────────────────┘
領域 内容
ヘッダー 開閉アイコン、カード画像、カード名
詳細 カードパック、クラス、分類、タイプ、数値、キーワード能力、能力テキスト等

詳細部分の具体的な構造は「05-04 カード詳細UI」で定義する。

6. 閉じた状態

履歴カードを閉じた状態でも、 回答したカードが何であったか確認できるようにする。 

┌────────────────────────────────────────────┐
│ ▶ [画像] 絶叫と愛絶の顕現・ルルナイ＆     │
│          ヴァーナレク                      │
└────────────────────────────────────────────┘
閉じた状態でも必ず表示するもの
  • 開閉状態を示すアイコン。
  • カード画像。
  • カード名。

カード画像を閉じた状態で非表示にはしない。

7. 展開した状態

履歴カードを展開すると、 ヘッダーの下へ回答カードの詳細情報を表示する。 

┌────────────────────────────────────────────┐
│ ▼ [画像] エルフクイーン                    │
├────────────────────────────────────────────┤
│ カードパック                               │
│ ○○○○○○                                   │
├────────────────────────────────────────────┤
│ クラス                  レアリティ         │
│ エルフ                  レジェンド         │
├────────────────────────────────────────────┤
│ 分類                    タイプ             │
│ フォロワー              宴楽・兵士         │
├────────────────────────────────────────────┤
│ コスト        攻撃力        体力           │
│   7 ▲           5 ▼           6            │
├────────────────────────────────────────────┤
│ キーワード能力                             │
│ 守護・突進                                 │
├────────────────────────────────────────────┤
│ カード能力テキスト全文                     │
└────────────────────────────────────────────┘
  • 展開してもヘッダー部分はそのまま表示する。
  • カード画像も引き続き表示する。
  • 詳細情報はヘッダー直下へ表示する。
  • 詳細内容の高さに応じて履歴カード全体を伸ばす。

8. カード画像

履歴カードのヘッダーには、 回答したカードの画像を表示する。

  • 画像表示幅は80pxを基本とする。
  • 画像の縦横比は維持する。
  • 高さを固定して画像を変形させない。
  • 閉じた状態でも表示する。
  • 展開状態でも同じ画像を表示する。
基本イメージ

▶ ┌────────┐
  │        │
  │ CARD   │  ← 幅80px
  │ IMAGE  │
  │        │
  └────────┘
     カード名

9. カード名

カード名は履歴カードの主要情報であるため、 画像の横に目立つ形で表示する。

  • カード名は太字とする。
  • 最大2行での表示を基本とする。
  • 改行位置をカードごとに手動設定しない。
  • CSSおよびブラウザによる自然な折り返しを使用する。
  • スマートフォンでも約30文字程度を2行以内に収められる設計を目標とする。

長いカード名の例： 

絶叫と愛絶の顕現・ルルナイ＆ヴァーナレク

表示例： 

┌────────────────────────────────────────────┐
│ ▶ [画像] 絶叫と愛絶の顕現・ルルナイ＆ヴ   │
│          ァーナレク                        │
└────────────────────────────────────────────┘

改行位置は画面幅や文字サイズによって自然に変化してよい。

10. カード名の省略

現在想定しているカード名については、 可能な限り全文を表示する。

  • 通常は「…」による省略を行わない。
  • 既知の長いカード名を2行以内に表示できるようレイアウトを調整する。
  • 無理に1行へ収めない。
  • カード名の途中を独自ルールで短縮しない。
将来的に現在想定している長さを大幅に超えるカード名が登場した場合は、 レスポンシブ仕様側で再検討する。

11. アコーディオン操作

各履歴カードはアコーディオン形式とし、 カードごとに詳細情報を表示・非表示できる。 

閉じた状態

▶ [画像] カード名


      ↓ ヘッダーを押す


開いた状態

▼ [画像] カード名
────────────────
カード詳細
────────────────


      ↓ 再びヘッダーを押す


閉じた状態

▶ [画像] カード名
  • 閉じたカードを押すと展開する。
  • 開いたカードを押すと閉じる。
  • 開閉は同じヘッダー領域で操作する。
  • 開閉によって回答履歴そのものを削除しない。

12. クリック・タップ範囲

アコーディオンの操作対象を 小さな矢印アイコンだけに限定しない。

履歴カードのヘッダー全体を クリック・タップ可能な領域とする。 

┌────────────────────────────────────────────┐
│████████████████████████████████████████████│
│█ ▶ [画像] カード名                       █│
│████████████████████████████████████████████│
└────────────────────────────────────────────┘

↑
この領域全体が開閉操作の対象

以下のいずれを押しても同じ開閉処理を行う。

  • 矢印アイコン。
  • カード画像。
  • カード名。
  • カード名右側の余白。
  • ヘッダー上下の余白。
スマートフォンでは特に、 小さな矢印のみをタップさせるUIにはしない。 横長のヘッダー全体をタップ可能とすることで、 操作しやすさを確保する。

13. 開閉アイコン

履歴カードが現在開いているか閉じているかを 視覚的に判別できるよう、 ヘッダー内へ方向アイコンを表示する。

状態 表示例
閉じている ▶
開いている ▼

アイコンは状態変化に合わせて更新する。

具体的なアイコンデザインは最終デザイン調整時に変更可能とするが、 開閉状態が直感的に分かる表現を使用する。

14. 複数カードの同時展開

履歴カードは、それぞれ独立して開閉する。

1つのカードを開いたからといって、 それまで開いていた別のカードを自動で閉じない。 

▼ 3回目の回答
   └ 詳細表示

▶ 2回目の回答

▼ 1回目の回答
   └ 詳細表示
  • 複数の履歴カードを同時に展開可能とする。
  • 各履歴カードが独立した開閉状態を持つ。
  • 別カードを開いても現在開いているカードは維持する。

これにより、 異なる回答カードの情報を続けて比較しやすくする。

15. 新しい回答追加時の動作

新しい回答の判定が完了した場合、 その回答を履歴の最上部へ追加する。

回答前： 

2回目
1回目

3回目の回答完了後： 

3回目 ← 新規追加
2回目
1回目
  • 既存の回答履歴の並び順を崩さない。
  • 新しい回答だけを最上部へ追加する。
  • 過去の回答内容を書き換えない。
  • 過去の判定結果もそのまま保持する。

16. 新規回答カードの初期開閉状態

回答直後のカードは、 判定内容をプレイヤーがすぐ確認できる必要がある。

新しく追加された回答カードは、 回答直後は展開状態で表示することを基本とする。

プレイヤーは内容を確認した後、 ヘッダーを押して閉じることができる。 

回答する

   ↓

判定完了

   ↓

▼ 今回回答したカード
   ├ カードパック
   ├ クラス
   ├ レアリティ
   ├ 分類
   ├ タイプ
   ├ コスト
   ├ 攻撃力
   ├ 体力
   ├ キーワード能力
   └ 能力テキスト

▶ 過去のカード
過去カードをプレイヤーが展開していた場合、 新規カード追加だけを理由に自動で閉じない。

17. 同一カードを複数回答した場合

Shado Guesserでは、 過去に回答したカードと同じカードを 再び回答すること自体は禁止しない。

そのため、同一カードが履歴へ複数回存在する場合がある。 

3回目
▶ [画像] エルフクイーン

2回目
▶ [画像] ○○○○

1回目
▶ [画像] エルフクイーン
  • 同一カードであっても別の回答履歴として追加する。
  • 古い同一カード履歴を上書きしない。
  • 履歴上で自動統合しない。
  • 「回答済み」等の警告表示を履歴側には追加しない。

18. 2人対戦時の履歴

2人対戦では、 両プレイヤーの回答を 1つの共通履歴へ追加する。

プレイヤーごとに別々の履歴欄は作成しない。

回答順が以下だった場合： 

1. プレイヤーAが回答
2. プレイヤーBが回答
3. プレイヤーAが回答

画面上の履歴は以下となる。 

3番目に回答されたカード

2番目に回答されたカード

1番目に回答されたカード
  • 両プレイヤーの回答を同一履歴へ時系列で追加する。
  • 最新回答を最上部にする。
  • 回答者ごとに履歴を分離しない。
  • 履歴カードの基本デザインはソロと共通とする。

19. 対戦時に回答者を履歴へ表示しない

2人対戦であっても、 各履歴カードへ回答者名やプレイヤーカラーを付与しない。

履歴カード上では以下を行わない。
  • 「Aさんの回答」等の名前表示。
  • プレイヤーA・Bによる背景色の変更。
  • 回答者ごとの枠線色変更。
  • 回答者アイコンの追加。
  • 回答者ごとの左右配置。

実際の履歴表示イメージ：

▼ [画像] 3番目に回答されたカード
   └ 詳細

▶ [画像] 2番目に回答されたカード

▶ [画像] 1番目に回答されたカード

見た目はソロモードと同じものを使用する。

誰が回答したかを視覚的に区別するために 履歴UIそのものを複雑化しない。 対戦でも、カードの判定結果を確認するという 履歴本来の役割を優先する。

20. ソロモードの履歴

ソロモードでは、 プレイヤー自身の回答を順番に履歴へ追加する。 

最新回答
↓
▼ 4回目

▶ 3回目

▶ 2回目

▶ 1回目

最大10回の回答が行われるため、 通常は最大10件の履歴カードが表示される。

21. デイリーモードの履歴

デイリーモードの回答履歴UIは、 ソロモードと同一構造とする。

  • 最新回答を上に表示する。
  • 履歴カードはアコーディオン形式。
  • カード画像を常時表示する。
  • 最大10回の回答を表示する。
  • デイリー専用の履歴カードデザインは作らない。

22. 2人出題モードの履歴

2人出題モードでは、 回答者がゲームを開始した後の回答履歴を表示する。

基本的な履歴UIはソロモードと同一とする。

  • 回答者の回答を履歴へ追加する。
  • 出題者が正解カードを設定した操作は回答履歴へ含めない。
  • 正解カード設定時点で履歴カードを生成しない。
  • 実際のGuessのみ履歴へ追加する。

23. 履歴のスクロール

履歴専用領域へ固定高さを設定し、 その中だけをスクロールさせる構造は基本的に使用しない。

回答数や展開状態に応じて、 ページ全体が縦方向へ伸びる構造とする。 

入力UI
   ↓
履歴3
   ↓
履歴2
   ↓
履歴1
   ↓
ページ下部
  • 履歴カードが増えた場合はページ自体を縦へ伸ばす。
  • 通常のブラウザスクロールを利用する。
  • 履歴エリア内部へ別の縦スクロールバーを基本的に設けない。
  • 展開したカード詳細を途中で切らない。

24. 新規回答追加時の画面位置

新しい履歴カードを追加した際、 プレイヤーが新しい判定結果を確認できる必要がある。

ただし、急激なスクロール移動によって 操作感を損なわないようにする。

  • 新規履歴が画面外となる場合は、最新結果を確認しやすい位置への誘導を考慮する。
  • 不要な大幅スクロールは避ける。
  • 具体的な自動スクロール挙動は実機テストで最終決定する。
自動スクロールの有無・アニメーション時間は、 PCとスマートフォンで使用感を確認して決定する。 基本的な履歴構造には影響しないため、 現段階では最終確定事項としない。

25. 判定色と履歴カード

回答したカードの詳細部分には、 正解カードとの比較結果を色や記号で表示する。

ただし、履歴カード全体を 単一の正解・不正解色で塗りつぶすものではない。

判定は主にカード詳細内の各項目単位で表示する。

  • 一致。
  • 不一致。
  • 部分一致。
  • 数値の上下。
  • 比較対象外。

判定色・▲・▼・－等の詳細は 「05-05 判定表示」で定義する。

26. カード能力テキスト

展開状態では、 カードの能力テキスト全文も履歴カード内へ表示する。

ただし、能力テキストは正解判定項目ではない。

  • 能力テキストはカード詳細の最下部に表示する。
  • 「Effect」「効果」等の専用見出しは設置しない。
  • 長文でも全文表示する。
  • 能力テキストのために横スクロールを発生させない。

27. 履歴データとして保持する情報

履歴カードを描画するため、 回答ごとに必要なデータを保持する。

情報 用途
回答カードID 回答カードの特定
カード名 ヘッダー表示
カード画像 ヘッダー表示
カード詳細情報 展開時の表示
各項目の判定結果 判定色・記号表示
回答順 履歴の並び順管理
2人対戦では通信同期のために内部データ上で 回答者情報を保持することは可能である。 ただし、 履歴カードUI上では回答者を視覚的に区別しない。

28. WordPress組み込み時の構造

WordPressテーマとのCSS競合を避けるため、 履歴関連クラスには sg- プレフィックスを使用する。 

<div class="sg-history">

    <article class="sg-history-card">

        <button
            class="sg-history-header"
            type="button"
            aria-expanded="false"
        >

            <span class="sg-history-arrow">▶</span>

            <img
                class="sg-history-image"
                src="..."
                alt=""
            >

            <span class="sg-history-name">
                カード名
            </span>

        </button>

        <div class="sg-history-detail">
            ...
        </div>

    </article>

</div>
  • .history 等の一般的すぎる名前は避ける。
  • ヘッダー全体を1つの操作要素として扱える構造にする。
  • JavaScriptは各履歴カードの開閉状態を独立して管理する。
  • WordPress側のグローバルCSSへ依存しない。

29. アクセシビリティ上の基本方針

アコーディオンのヘッダーは、 見た目だけのクリック領域ではなく、 操作可能な要素として実装する。

  • ヘッダーには button 等の操作可能要素を使用する。
  • 開閉状態を aria-expanded 等で表現可能な構造とする。
  • カード画像単体へ別の不要なクリック処理を付けない。
  • ヘッダー全体を1つの操作対象とする。

30. 履歴表示で設置しない機能

現時点では以下の機能を履歴UIへ設置しない。

  • 回答履歴の削除。
  • 回答履歴の編集。
  • 履歴順序の並び替え。
  • 回答者別フィルター。
  • プレイヤー別の色分け。
  • 履歴のページ分割。
  • 回答済みカードの重複統合。
  • 「すべて開く」ボタン。
  • 「すべて閉じる」ボタン。
