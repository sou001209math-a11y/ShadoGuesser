Shado Guesser 基本設計書

06：サーバー・Cloudflare設計

本設計書では、 Shado GuesserのCloudflare環境における サーバー構成、 API、 D1、 Durable Objects、 WebSocket、 ゲーム状態管理、 Daily生成・停止、 回答判定、 再接続、 タイムアウト、 セッション管理、 冪等処理、 自動削除等を定義する。

ゲームの正式な状態・正解・回答回数・判定・手番・deadline・勝敗等は サーバー側をSource of Truth とする。

1. 基本方針

  • Frontend：Cloudflare Pages。
  • API入口：Cloudflare Workers。
  • 永続Data：Cloudflare D1。
  • 進行中Game State：Durable Objects。
  • 2人モードのRealtime通信：WebSocket。
  • WebSocketはHibernationを利用可能な構成。
  • 正解Cardは通常Game EndまでServer側に保持。
  • 正式なGuess判定はServer側。
  • Client Stateを正式Stateとして信用しない。
  • 初期版では常時起動VPS / Node.js Serverを必須としない。

  • HTML配信。
  • CSS配信。
  • JavaScript配信。
  • Version別Search Index配信。
  • 公開Static Asset配信。

4. Cloudflare Workers

  • Public API入口。
  • Request形式検証。
  • Token認証。
  • D1 Access。
  • Current Data Version取得。
  • 回答対象範囲生成。
  • Game作成。
  • Daily Config取得・作成。
  • Daily Control確認。
  • Durable Object Routing。
  • WebSocket Upgrade Routing。
  • 安全なError Response生成。

Workers自身のJavaScript Memoryへ 進行中Gameの正式Stateを保存しない。

8. Durable Object Storage

新規DOでは SQLite-backed Durable Object Storageを基本構成とする。

Game StateはJavaScript Memoryだけではなく DO Storageへ保存する。

DOが休止・再起動・Hibernation復帰しても StorageからGame Stateを復元可能とする。
