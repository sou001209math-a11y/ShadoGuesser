Shado Guesser 基本設計書

05-09：サジェスト・細部仕様

本設計書では、 Shado Guesserのカード名入力時に表示する サジェスト候補の検索条件、 検索データ取得方式、 表示・選択・閉じる動作、 回答ボタンとの連携、 日本語IME、 Data Versionとの整合、 requestId、 Battleの手番・deadline、 Hint、 Daily停止、 再接続等、 ゲーム画面全体に共通する細部UI仕様を定義する。

1. 目的

Shadowverseには長いカード名が存在するため、 正式カード名の完全入力を必須にすると ゲーム操作の負担が大きくなる。

Shado Guesserでは、 カード名を途中まで入力すると候補を表示し、 候補から正式なカードを選択したうえで 回答できるサジェスト方式を採用する。

カード名検索はブラウザ内で実行し、 文字入力のたびにWorkers / D1へ 検索Requestを送信しない。

基本方針
  • カード名の部分一致検索。
  • 2文字以上で検索開始。
  • 候補は最大10件。
  • 現在のゲームで回答可能なカードのみ検索対象。
  • Version別の静的Search Indexを使用。
  • 検索処理はBrowser内で実行。
  • 文字入力ごとのWorker通信なし。
  • 文字入力ごとのD1検索なし。
  • 候補選択でcard_idを確定。
  • 候補選択だけでは回答しない。
  • 回答は「回答する」Buttonのみ。
  • Enterキーでは回答しない。
  • 正式なGame StateはServerを正とする。

候補一覧はカード名入力欄の直下へ表示する。

  • 候補行全体をClick / Tap可能とする。

9. Search Indexへ含めない情報

  • 現在の正解card_id。
  • Daily正解card_id。
  • Battle正解card_id。
  • 2人出題で設定された正解card_id。
  • Session Token。
  • Reconnect Token。
  • Authorization。
  • 非公開Server State。

また初期版では、 Suggestionに不要な skill_text / atk / life / cost / tribes / keywords等も 原則として含めない。

Browser内検索性能が十分であれば debounceは必須としない。

48. 回答成功後

正式Guessが成立し、 Gameが継続する場合のみ 次のInputへ戻る。

  • inputValueを空にする。
  • selectedCardId解除。
  • Suggestionを閉じる。
  • History更新。
  • 残り回答数更新。
  • Server Stateを反映。

50. 通信失敗時

  • Clientだけで成功扱いにしない。
  • Historyへ勝手に追加しない。
  • 回答数を勝手に減らさない。
  • 同一requestIdによるRetry / 状態確認を可能にする。
  • 正式Server Stateを再取得する。

81. WordPress等への組み込み

  • Shado Guesserは独立Webアプリとして動作可能。

  • CSSは sg- prefix。
  • WordPress固有Functionへ依存しない。
  • WordPress PHPへSearch処理を依存させない。
  • Host Siteのinput / button Styleへ依存しない。

82. Accessibility

  • Answerはbutton要素。
  • Candidateもbutton等の操作可能要素を使用可能。
  • disabled状態は実際の属性でも表現。
  • Focus表示を完全に消さない。
  • Candidate選択領域を十分確保。

  • 相手Turn中の回答Request。
