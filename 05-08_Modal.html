Shado Guesser 基本設計書

05-08：モーダル

本設計書では、Shado Guesserにおいて ゲーム進行へ大きな影響を与える操作に使用する 確認モーダルの構造、表示内容、閉じ方、確定操作、 モードごとの利用条件、およびサーバー状態との関係を定義する。

1. 目的

確認モーダルは、 プレイヤーの誤操作によって 現在のゲームを意図せず終了してしまうことを防ぐために使用する。

特に「降参」や「2人対戦からの退出」は、 確定後に現在のゲームへ戻れないため、 最初のボタン押下だけで処理せず 1段階の確認を行う。

基本方針
  • ブラウザ標準のconfirmダイアログは使用しない。
  • Shado Guesser専用モーダルを使用する。
  • 不可逆性の高い操作を中心に確認モーダルを使用する。
  • 閉じる操作と確定操作を明確に分離する。
  • Enterキーだけでは危険操作を確定しない。
  • ESCキーではモーダルを閉じる。
  • 背景オーバーレイを押した場合も閉じる。
  • 右上の×でも閉じる。
  • 正式な終了状態はサーバー側を正とする。

2. 使用対象

操作 確認モーダル 理由
ソロの降参 使用する 正解公開・ゲーム終了となるため
デイリーの降参 使用する 正解公開・ゲーム終了となるため
2人出題・回答者の降参 使用する 回答者側ゲーム終了となるため
2人対戦中の明示的退出 使用する 退出者の即時敗北となるため
回答 使用しない 通常のゲーム操作であるため
ヒント使用 使用しない ゲーム終了操作ではないため
サジェスト選択 使用しない 回答確定ではないため
回答履歴の開閉 使用しない 自由に戻せるUI操作であるため

3. モード別の降参・退出

モード 操作 結果
ソロ 降参 ゲーム終了・正解公開
デイリー 降参 ゲーム終了・正解公開
2人出題・回答者 降参 回答者ゲーム終了・正解公開
2人出題・出題者 正解設定後の退出 回答者ゲームを終了させない
2人対戦 退出 退出したプレイヤーの即時敗北

2人出題では 回答者のみ「降参」操作を使用する。

正解設定後の出題者がページを閉じる・切断する・退出することは、 回答者の降参として扱わない。

モーダルは画面全体を覆うオーバーレイ上に表示する。

│       │ モーダルタイトル        [×] │       │
│       │                              │       │
│       │ 説明文                       │       │
│       │                              │       │
│       │        [ 確定ボタン ]        │       │
│       │                              │       │

  • 背景に半透明オーバーレイを表示する。
  • モーダル本体を画面中央付近へ表示する。
  • タイトルを表示する。
  • 右上に閉じる「×」を表示する。
  • 確定した場合に何が起こるかを説明する。
  • 最下部に確定ボタンを配置する。

6. 降参モーダルを開いた時点

ゲーム画面の「降参」ボタンを押しただけでは、 ゲーム状態を終了へ変更しない。 

[ 降参 ]

   ↓

確認モーダル

   ↓

まだゲーム終了ではない
  • 回答回数を消費しない。
  • 正解カードを公開しない。
  • 終了履歴を作成しない。
  • 結果画面へ移行しない。

7. 降参の確定

モーダル内の 「降参する」を明示的に押した場合のみ、 サーバーへ降参確定要求を送信する。 

[ 降参する ]

       ↓

サーバーへ降参要求

       ↓

サーバー側で状態確認

       ↓

降参確定

       ↓

ゲーム終了

       ↓

正解カード公開

       ↓

結果画面
  • 降参を正式な終了理由とする。
  • 回答入力を終了する。
  • 新しいヒント使用を不可にする。
  • それまでの回答履歴を維持する。
  • 正解カードを公開する。
  • 結果画面へ移行する。

8. 降参はGuessではない

降参そのものはカードGuessではないため、 回答回数へ含めない。 

6回回答

↓

降参

↓

結果

回答数：6回

「降参」を新しい回答履歴カードとして追加しない。

9. ソロモード

ソロモードでは 降参確認モーダルを使用する。

  • 降参可能。
  • 確認モーダルあり。
  • 降参確定後にゲーム終了。
  • 正解カードを公開。
  • 結果画面へ移行。

10. デイリーモード

デイリーモードでも ソロと同じ降参モーダルを使用する。

  • 降参可能。
  • 確認モーダルあり。
  • 降参後に正解カードを公開。
  • 結果画面へ移行。
  • X共有時には正解情報を含めない。

11. 2人出題：回答者の降参

2人出題では、 回答者がゲームを続けることを諦める場合に 降参できる。

  • 回答者に「降参」を表示する。
  • ソロと同じ確認モーダルを使用する。
  • 「降参する」確定後に回答者側ゲームを終了する。
  • 正解カードを公開する。
  • 降参までの回答履歴を維持する。
  • 降参は回答回数に含めない。

2人出題ではヒント機能を使用しないため、 降参モーダルにもヒントに関する説明は表示しない。

12. 2人出題：出題者

出題者が正解カードを設定し、 回答者のゲームが開始された後は、 出題者の接続をゲーム継続の必須条件としない。

  • 出題者の退出を回答者の降参として扱わない。
  • 出題者の退出だけで正解カードを公開しない。
  • 出題者の切断だけで回答者ゲームを終了しない。
  • 回答者はサーバー側に保持された正解を使ってゲームを継続する。

13. 2人対戦の退出

2人対戦では、 通信切断とは別に プレイヤーが明示的に対戦を終了する 「退出」操作を用意する。

明示的な退出は即時敗北として扱う。

一時的な通信切断と同じ処理にはしない。

14. 対戦退出モーダル

対戦中に 「退出」を押した場合、 以下の確認モーダルを表示する。

対戦から退出しますか？　　　　【×】

退出するとあなたの敗北となり、
この対戦は終了します。

           [ 退出する ]

15. 対戦退出の確定

「退出する」を押した場合、 サーバーへ明示的退出要求を送信する。 

[ 退出する ]

       ↓

サーバーへ退出要求

       ↓

サーバー状態確認

       ↓

退出者：敗北

相手：勝利

       ↓

対戦終了
  • 退出した本人を敗北とする。
  • 相手プレイヤーを勝利とする。
  • 通信切断用の30秒再接続猶予を適用しない。
  • 対戦を即時終了状態にする。
  • 終了後に正解カードを公開する。

16. 退出ボタン押下だけでは敗北しない

ゲーム画面上の 「退出」ボタンを最初に押した時点では、 まだ敗北を確定しない。 

[ 退出 ]

↓

確認モーダル

↓

× / ESC / 外側クリック
→ ゲーム継続


[ 退出する ]
→ サーバーへ退出要求

17. 通信切断との違い

状態 処理
「退出する」を確定 明示的退出・即時敗北
一時的な通信切断 30秒再接続猶予
ネットワーク障害 再接続処理
ブラウザが突然終了 切断として処理

サーバーが明示的退出要求を受け取っていない場合、 単なる通信切断を 「退出するを押した」とみなさない。

18. ×ボタン

右上の「×」は 確認操作をキャンセルしてゲームへ戻るために使用する。

  • モーダルを閉じる。
  • 降参を確定しない。
  • 退出を確定しない。
  • 回答回数を消費しない。
  • サーバーへ終了要求を送信しない。

19. モーダル外クリック

モーダル本体の外側にある 背景オーバーレイをクリック・タップした場合も、 モーダルを閉じる。

  • オーバーレイ → 閉じる。
  • モーダル内部 → 閉じない。
  • 本文 → 閉じない。
  • 確定ボタン → 確定処理。

20. ESCキー

モーダル表示中にESCキーを押した場合は、 モーダルを閉じる。

ESCキー = キャンセル
  • 降参を確定しない。
  • 退出を確定しない。
  • ゲームへ戻る。

21. Enterキー

Enterキーでは、 モーダル内の不可逆操作を確定しない。

  • Enter → 降参しない。
  • Enter → 退出しない。
  • Enter → 確定ボタンを自動実行しない。

不可逆操作には 明示的なボタン操作を必要とする。

22. モーダルを閉じる方法

操作 閉じる 確定
右上の× ○ しない
背景オーバーレイ ○ しない
ESC ○ しない
モーダル本文 × しない
Enter × しない
確定ボタン 処理完了後 する

23. モーダル表示中の背後UI

モーダルが開いている間は、 背後のゲームUIを直接操作できないようにする。

  • 回答ボタンを押せない。
  • カード名入力欄を操作できない。
  • ヒントを押せない。
  • 履歴アコーディオンを操作できない。
  • サジェスト候補を選択できない。
  • 背後の別ボタンをクリックできない。

24. モーダルはゲーム時間を停止しない

確認モーダルを開いても、 サーバー側のゲーム進行・締切時刻を停止しない。

特に2人対戦では、 自分の手番中に退出モーダルを開いていても 120秒の手番制限時間は進み続ける。 

自分の手番

残り 30秒

↓

退出モーダルを開く

↓

モーダルを30秒以上開いたまま

↓

サーバー上では時間切れ成立

モーダルを開くことで プレイヤーが手番時間を無限に停止できる仕様にはしない。

25. モーダル表示中にゲーム状態が変化した場合

オンラインゲームでは、 モーダル表示中でも サーバー側のゲーム状態が変化する可能性がある。 

退出モーダル表示中

↓

相手が正解

↓

サーバーで対戦終了

↓

退出モーダルを閉じる

↓

結果画面へ移行

モーダルのローカル表示状態より サーバー側の正式ゲーム状態を優先する。

26. 時間切れが成立した場合

2人対戦で退出確認中に 手番の120秒が経過した場合も、 正式なタイムアウト判定はサーバー側で行う。

  • モーダルによってdeadlineを延長しない。
  • モーダルによって時間切れ判定を無効化しない。
  • サーバーで時間切れが成立した場合はその状態を反映する。
  • ゲーム継続中なら新しい状態に合わせてUIを復元する。

27. 背景オーバーレイ

モーダル表示中は、 背景へ半透明オーバーレイを表示する。

  • ゲーム画面を完全には消さない。
  • 背後が認識できる程度の半透明とする。
  • モーダル本文との十分なコントラストを確保する。
  • ゲーム表示領域全体を覆う。

28. 背景スクロール

モーダル表示中は、 背後のページが意図せずスクロールしないようにする。

特にスマートフォンで、 モーダルを操作しようとした際に 背景だけが移動しないようにする。

具体的なスクロール固定方式は、 独立Webアプリおよび将来のホストサイト組み込みの双方で 問題がない方法を実装時に選択する。

29. モーダルの横幅

PCでは適切な最大幅を持たせ、 スマートフォンでは画面幅へ追従する。

  • 固定幅だけで実装しない。
  • 画面幅を超えない。
  • 左右に最低限の余白を確保する。
  • PCではmax-widthを利用する。
  • スマートフォンではほぼ画面幅を利用できる。

30. スマートフォン

スマートフォンでは、 タイトル・本文・確定ボタンを縦方向に配置し、 指で操作しやすい領域を確保する。 

┌──────────────────────────────┐
│ 降参しますか？          [×] │
│                              │
│ 正解のカードが表示され、     │
│ このゲームは終了します。     │
│                              │
│      [   降参する   ]        │
└──────────────────────────────┘
  • 確定ボタンをタップしやすくする。
  • ×も十分なタップ領域を持つ。
  • 本文を読みやすい文字サイズにする。
  • 横スクロールを発生させない。

31. ×ボタンのタップ領域

画面上は「×」だけを表示しても、 実際のクリック・タップ領域は記号より広く確保する。

小さな「×」文字そのものを 正確に押させるUIにはしない。

32. 確定ボタン

降参・退出等の確定ボタンは、 通常操作と区別しやすいデザインとする。

操作 確定ボタン
降参 降参する
2人対戦退出 退出する
  • 「OK」だけにしない。
  • 「はい」だけにしない。
  • 実行される操作名を明記する。

33. 二重実行防止

確定ボタンを連打しても、 同じ終了要求を複数回成立させない。 

[ 降参する ]

      ↓

[ 処理中... ]

      ↓

操作不可

      ↓

サーバー応答

      ↓

結果画面
  • 確定押下直後にボタンを無効化する。
  • 同一終了処理を連続送信しない。
  • サーバー側でも重複処理を防止する。

34. 終了要求ID

通信状況によって同じ降参・退出要求が 再送される可能性を考慮し、 要求を識別できるIDを付与できる構造とする。 

requestId
+
action
+
gameId / roomId

同じ requestId による終了要求を 二重の降参・二重の敗北として処理しない。

具体的な冪等処理は 06 サーバー・Cloudflare設計で定義する。

35. 確定要求送信後は閉じない

降参・退出の確定要求を送信した後は、 処理結果が確定するまで ×・背景クリック・ESCによるキャンセルを無効化する。

確定前は閉じられる。確定要求送信後は閉じない。

36. 通信失敗時

確定ボタンを押した後に通信エラーが発生した場合、 クライアントだけの判断で 降参・敗北を確定したことにはしない。

  • サーバー側のゲーム状態を確認する。
  • 既に処理済みなら確定結果へ移行する。
  • 未処理なら安全に再試行できる構造とする。
  • ローカル状態だけで勝敗を決定しない。

37. モーダル表示中の通信切断

2人対戦で退出モーダルを表示している最中に ネットワーク接続が切れた場合、 明示的退出要求がサーバーへ成立していなければ 通常の通信切断として扱う。

「退出モーダルを開いていた」 というクライアント状態だけを理由に 即敗北にはしない。

38. ブラウザ標準confirmを使用しない

使用しない：

if(confirm("降参しますか？")){
    ...
}

Shado Guesserの画面デザインと統一された 専用モーダルを使用する。

39. beforeunload

ページ更新・タブ終了等について、 Shado Guesser独自の終了確認モーダルで ブラウザ操作そのものを強制的に阻止しない。

  • F5更新を独自モーダルで阻止しない。
  • タブを閉じるたびに独自確認を出さない。
  • ソロゲームの状態保持を強制しない。

2人対戦の突然のページ終了は サーバー側では通信切断として扱い、 30秒再接続処理へ移行する。

40. モーダルの重複表示

同時に複数の確認モーダルを重ねて表示しない。

  • 降参モーダルを二重生成しない。
  • 退出モーダルを二重生成しない。
  • アクティブな確認モーダルは原則1つ。

41. モーダル状態

JavaScript側では、 現在表示中のモーダル種別と 処理状態を判別可能にする。 

例：

modalState = null

modalState = {
    type: "surrender",
    status: "confirm"
}

modalState = {
    type: "leave",
    status: "submitting"
}

上記の変数構造は実装例であり、 最終的なコード上の名称を固定するものではない。

44. ホストサイトとの競合対策

Shado Guesserは独立Webアプリとして実装するが、 将来的なWordPress等への組み込みも考慮する。

  • ゲームUIは原則 #sg-app 内で管理する。
  • 専用クラスには sg- を付ける。
  • .modal 等の一般名称だけを使用しない。
  • WordPress固有モーダル機能へ依存しない。
  • 外部サイトのJavaScriptへ依存しない。
  • z-indexは組み込み先でもモーダルが前面になるよう調整可能とする。

45. アクセシビリティ

モーダルは見た目だけのポップアップではなく、 ダイアログとして認識可能なHTML構造とする。

  • role="dialog" を使用する。
  • aria-modal="true" を使用する。
  • タイトルとの関連付けを行う。
  • 説明文との関連付けを行える構造とする。
  • ×には「閉じる」の意味を付与する。
  • 操作要素にはbutton要素を使用する。

46. キーボードフォーカス

PCでは、 モーダル表示中に背後のゲームUIへ 不用意にフォーカスが移らないようにする。

  • モーダル内へフォーカスを移す。
  • Tab操作をモーダル内で扱う。
  • 閉じた後は適切な元操作へ戻す。
  • Enterを危険操作の自動確定に使用しない。
  • ESCで閉じられる。

47. モーダル内に表示しないもの

  • 正解カード。
  • 回答履歴。
  • カード詳細。
  • サジェスト。
  • ゲーム全体のルール説明。
  • 長大な警告文。
  • 不要な多数のボタン。
  • 内部的な正解card_id。
  • 再接続トークン。
  • 内部ゲーム状態。

48. 専用キャンセルボタン

初期版では、 大きな「キャンセル」専用ボタンを必須とはしない。

以下をキャンセル方法とする。

  • ×
  • 背景オーバーレイ
  • ESC

スマートフォン実機テストで キャンセル操作が分かりにくい場合は、 「戻る」または「キャンセル」ボタンを追加できる。

49. 結果画面との違い

項目 確認モーダル 結果画面
目的 不可逆操作の事前確認 ゲーム終了結果の確認
キャンセル 確定前なら可能 ゲームは終了済み
正解カード 表示しない 表示する
回答履歴 表示しない 閲覧可能
ゲーム状態 原則進行中 終了済み

ゲーム結果を 小型モーダルだけで完結させない。

52. モーダルで行わないこと

  • 降参ボタンを押した瞬間にゲーム終了する。
  • 退出ボタンを押した瞬間に敗北確定する。
  • Enterだけで降参・退出を確定する。
  • ESCで確定する。
  • 背景クリックで確定する。
  • ブラウザ標準confirmを使用する。
  • 複数モーダルを重ねる。
  • モーダル表示中に背後の回答UIを操作させる。
  • モーダル表示中に2人対戦の時間を停止する。
  • クライアントだけで正式な勝敗を決定する。
  • 単なる通信切断を明示的退出として扱う。
  • 2人出題の出題者退出だけで回答者ゲームを終了する。

55. 課題・実装時調整事項

以下は実装後の実機確認で最終調整する。

  • モーダルの具体的な最大横幅。
  • 背景オーバーレイの透明度。
  • 降参・退出ボタンの具体的な色。
  • ×ボタンの具体的なサイズ。
  • 表示・非表示アニメーションの有無。
  • スマートフォンでの上下余白。
  • 背景スクロールの具体的な固定方法。
  • ホストサイトへ組み込む場合のz-index。
  • 専用キャンセルボタンを追加する必要があるか。
  • 対戦退出時の最終的な説明文。
  • 終了要求送信中のローディング表現。

これらは基本的なモーダル操作ルールを変更せず、 主にCSS・実機確認によって調整する。
